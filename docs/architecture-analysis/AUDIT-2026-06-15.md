## 1. Resumen ejecutivo

> Conclusión: **el sistema es operativamente sano pero tiene 5 problemas CRÍTICOS de aislamiento multi-tenant y cálculo fiscal que requieren acción antes que cualquier refactor**.

1. **CRÍTICA — multi-tenant**: `calcular_comisiones_vendedor(p_vendedor_id)` no filtra por `tenant_id`; usuario de Tenant A puede leer comisiones de Tenant B
2. **CRÍTICA — multi-tenant**: edge function `admin-management` permite a superadmin crear usuarios en cualquier tenant sin audit; aún sin trail
3. **CRÍTICA — ITBIS**: `src/components/common/pdf/orderPDF.js:96` divide `itbis_pct` entre 100 → calcula ITBIS **100x menor** en PDFs de orden de compra
4. **CRÍTICA — DGII**: `supabase/functions/emitir-fiscal/dgii_xml_builder.ts:138, 1035` **hardcodea 0.18** y genera `<TotalITBIS>` sin sufijo (DGII rechaza con 400)
5. **ALTA — DGII**: no hay `UNIQUE` en `documentos_fiscales(factura_id)` → race condition puede crear 2 e-CF para misma factura
6. **ALTA — multi-tenant**: `get_presupuesto_compras(p_tenant_id)` y `get_productos_paginados()` no validan que `p_tenant_id` == `get_user_tenant()`
7. **ALTA — DGII**: `dgii_anular_ecf(rango)` actualiza estado sin chequeo previo → puede anular e-CF aceptados (impacto legal)
8. **ALTA — multi-tenant**: webhook `dgii-callback` es público y solo autentica por TrackId; si un atacante adivina/conoce TrackId, puede alterar estados
9. **CONFIRMADO — ciclos**: 8 import cycles detectados, todos pasan por `PanelContext.jsx`. Refactor mecánico, bajo riesgo
10. **CONFIRMADO — acoplamiento**: 99 archivos importan `supabase` directamente; 9 componentes "visuales" hacen consultas BD. `useVentas.js` con 1156 LOC es god hook
11. **CONFIRMADO — DGII modular**: las 3 comunidades DGII de Graphify (Document/Certification/Commercial) reflejan separación real de runners por flujo (sano)
12. **CONFIRMADO — tipo 33 DGII no implementado**: solo XML de prueba, no envío. Tipo 34 (Nota de Crédito) completo
13. **CONFIRMADO — docs/ están al día** (las creé hoy); CLAUDE.md fue extendido por `graphify claude install` con sección apropiada
14. **HALLAZGO NUEVO — meta_webhook_events.tenant_id NULLABLE**: eventos sin tenant_id no se filtran por RLS
15. **NO CONFIRMADO — alcance real de SECURITY DEFINER**: el agent identificó 5 funciones de riesgo, pero no listó las 100+ funciones SECURITY DEFINER del proyecto. Hay que iterar

**Recomendación general**: ejecutar **Fase 0 (Seguridad inmediata)** YA — son 5 fixes contenidos. Antes de cualquier refactor grande, ejecutar **Fase 1 (Pruebas)** para tener red de seguridad sobre ITBIS y aislamiento.

```sql
SELECT t.table_name
FROM information_schema.tables t
```

```
3. emitir-fiscal valida factura no esté ya emitida (existingDoc check)
4. Crea documentos_fiscales estado='procesando'
5. dgiiDirectoEmitirFactura:
   a. get_next_encf (atómico)
   b. buildEcfXml
   c. loadAndParseP12
   d. signEcfXml (XAdES-BES)
   e. uploadSignedXml a bucket ecf-xmls
   f. authenticate DGII (Semilla)
   g. POST /recepcion/api/FacturasElectronicas
6. UPDATE documentos_fiscales: estado='emitido', estado_dgii='enviado', track_id, encf
7. [ASYNC] DGII → POST /functions/v1/dgii-callback con ARECF
8. procesarArecf → UPDATE estado_dgii='aceptado'/'rechazado'/'aceptado_condicional' + log
```
